Keyboard event utility module that normalizes browser inconsistencies when extracting key codes, key values, and X11 keysym values from `KeyboardEvent` objects across legacy and modern browsers.

## Key Components

| Export | Description |
|--------|-------------|
| `getKeycode(evt)` | Returns a normalized `KeyboardEvent.code` string, handling Firefox/Chrome quirks, Windows Virtual-Key fallbacks, modifier location disambiguation, and numpad key mapping |
| `getKey(evt)` | Returns a normalized `KeyboardEvent.key` string, patching Mozilla spec drift, iOS OS-leaked key names, and Chrome numpad bugs |
| `getKeysym(evt)` | Returns the most appropriate X11 keysym value for a key event, used for VNC/RFB protocol transmission |

## Usage Example

```javascript
import { getKeycode, getKey, getKeysym } from './util.js';

document.addEventListener('keydown', (evt) => {
    const code = getKeycode(evt);   // e.g. 'ShiftLeft', 'NumpadEnter'
    const key  = getKey(evt);       // e.g. 'Shift', 'Enter', 'a'
    const sym  = getKeysym(evt);    // e.g. 0xffe1 (XK_Shift_L)

    if (sym !== null) {
        sendKeysymToRemote(sym);
    }
});
```

## Notes

- Falls back gracefully through `evt.code` → `evt.keyCode` (via `vkeys` map) → `'Unidentified'` for `getKeycode`
- Handles platform-specific quirks: macOS `ContextMenu`→`MetaRight`, Safari right-Cmd location, Windows Japanese IME alternating symbols (`Zenkaku`/`Hankaku`, `Romaji`/`KanaMode`)
- `getKeysym` resolves X11 keysyms via `DOMKeyTable` for special keys, then falls back to Unicode codepoint lookup via `keysyms.lookup()`
- Part of the [MeshCentral](https://github.com/flamingo-stack/meshcentral) noVNC keyboard input pipeline
