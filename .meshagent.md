Handles WebSocket communication between MeshCentral server and MeshAgent clients, managing authentication, connection lifecycle, and bidirectional command processing.

## Key Components

- **`CreateMeshAgent(parent, db, ws, req, args, domain)`** — Factory function that initializes a MeshAgent session object upon WebSocket connection
- **`obj.send(data, func)`** — Sends string or binary data to the connected agent
- **`obj.sendBinary(data, func)`** — Sends binary-encoded data to the agent
- **`obj.close(arg)`** — Disconnects the agent with soft (1), hard (2), or silent (3) modes; handles cleanup of timers, tasks, and temporary node data
- **`dataAccounting()`** — Tracks inbound/outbound byte counts for traffic statistics
- **`ws.on('message')`** — Routes incoming agent frames; handles authenticated JSON commands and binary protocol messages including `MeshCommand_CoreModuleHash` (cmd 11) for meshcore version validation and update

## Usage Example

```javascript
// Called automatically by the WebSocket server on new agent connections
const agent = require('./meshagent').CreateMeshAgent(
  parent,  // WebSocket server parent
  db,      // Database instance
  ws,      // WebSocket connection
  req,     // HTTP upgrade request (includes clientIp)
  args,    // Server arguments (e.g., agentidletimeout)
  domain   // Domain configuration object
);

// Send a command to the agent
agent.send(JSON.stringify({ action: 'getinfo' }));

// Disconnect gracefully
agent.close(1); // Soft disconnect

// Disconnect forcefully
agent.close(2); // Hard TCP disconnect
```

## Notes

- Agents flagged as **Temporary** (`0x20`) or **Recovery** (`0x40`) are fully removed from the database on disconnect
- Meshcore updates are managed via hash comparison; supports normal, recovery (`rcore`), tiny (`tcore`), and agent-recovery (`arcore`) core types
- Source: [`meshagent.js`](https://github.com/flamingo-stack/meshcentral/blob/main/meshagent.js)
