Windows Service launcher for MeshCentral, handling installation, removal, and lifecycle management (start/stop/restart) of the MeshCentral Remote Management Server as a Windows background service.

## Key Components

- **`start()`** — Main entry point that orchestrates service operations. Enforces Windows-only execution, resolves the `meshcentral.js` path across common install locations, and delegates to the appropriate service action.
- **Path Resolution** — Searches for `meshcentral.js` in four locations relative to `__dirname`: local directory, `node_modules/meshcentral/`, `../meshcentral/`, and parent directory.
- **Service Lifecycle Events** — Registers handlers for `install`, `uninstall`, `start`, `stop`, `alreadyinstalled`, and `invalidinstallation` events via `node-windows`.
- **Environment Variable Propagation** — Maps CLI args (`user`, `port`, `aliasport`, `mpsport`, etc.) into service environment variables prefixed with `mesh`.
- **Direct Launch** — When running as a Windows service (no lifecycle flags), calls `meshcentral.mainStart({ launch: true })` directly without spawning a child process.
- **Logging Helpers** — `logException`, `logInfoEvent`, `logWarnEvent`, `logErrorEvent` write to the Windows Event Log via `node-windows.EventLogger` and stdout/stderr.

## Usage Example

```bash
# Install as a Windows service
node winservice.js --install --port=443 --mpsport=4433

# Start the service
node winservice.js --start

# Restart the service
node winservice.js --restart

# Stop and remove the service
node winservice.js --stop
node winservice.js --uninstall
```

```javascript
// When invoked by Windows Service Manager (no flags), runs MeshCentral directly:
require('./meshcentral.js').mainStart({ "launch": true });
```

> **Note:** This file is Windows-only and exits with code `255` on any other platform. It depends on [`node-windows`](https://github.com/coreybutler/node-windows) and [`minimist`](https://github.com/minimistjs/minimist) being present under the resolved `cwd/node_modules/` path.
