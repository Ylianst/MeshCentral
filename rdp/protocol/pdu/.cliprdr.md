RDP Clipboard Redirection (CLIPRDR) channel implementation that handles clipboard data exchange between a client and server over the Remote Desktop Protocol.

## Key Components

### `Cliprdr` (Base Class)
Extends `EventEmitter`. Holds shared state including `transport`, `userId`, `serverCapabilities`, and `clientCapabilities`. Intended as a base for client/server implementations.

### `Client` (extends `Cliprdr`)
Full client-side implementation of the CLIPRDR channel automata. Manages the full clipboard negotiation lifecycle:

| Method | Description |
|---|---|
| `connect(gccCore, userId, channelId)` | Initializes channel and begins listening for PDUs |
| `send(message)` | Wraps messages in a Channel PDU Header and dispatches via transport |
| `recv(s)` | Parses incoming PDUs and routes to the appropriate handler |
| `recvMonitorReadyPDU(s)` | Responds to server ready signal by sending caps and format list |
| `sendClipboardCapsPDU()` | Advertises clipboard capabilities to the server |
| `sendFormatListPDU()` | Sends supported clipboard format list (Unicode text, OEM, bitmap, etc.) |
| `sendFormatDataRequestPDU(formatId)` | Requests clipboard data in a specific format (default: `0x0d`) |
| `sendFormatDataResponsePDU()` | Sends current clipboard content as UCS-2 encoded data |
| `recvFormatDataResponsePDU(s)` | Decodes incoming clipboard content and emits a `clipboard` event |
| `setClipboardData(content)` | Sets local clipboard content and triggers a format list negotiation |

## Usage Example

```javascript
const { Client } = require('./cliprdr');

const cliprdrClient = new Client(transport);

// Listen for clipboard data received from the remote server
cliprdrClient.on('clipboard', (text) => {
    console.log('Remote clipboard content:', text);
});

// Push local clipboard content to the remote session
cliprdrClient.setClipboardData('Hello from local clipboard!');
```

## Notes

- The `clipboard` event is emitted when the server sends clipboard data via `CB_FORMAT_DATA_RESPONSE`.
- `setClipboardData()` triggers a full CLIPRDR negotiation cycle to propagate the new content.
- Several PDU handlers (e.g., `recvFormatListResponsePDU`, `recvClipboardCapsPDU`) are stubbed and log nothing by default — debug logging is commented out throughout.
