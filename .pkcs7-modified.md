A modified implementation of PKCS#7 v1.5 cryptographic message syntax for Node.js, extending the `node-forge` library with support for EnvelopedData, EncryptedData, and SignedData content types.

## Key Components

### Message Conversion
- **`p7.messageFromPem(pem)`** — Parses a PEM-encoded PKCS#7 message into a message object
- **`p7.messageToPem(msg, maxline)`** — Serializes a PKCS#7 message object back to PEM format
- **`p7.messageFromAsn1(obj)`** — Constructs a PKCS#7 message from an ASN.1 object, dispatching to the appropriate content type handler

### Signed Data (`p7.createSignedData()`)
Returns a message object with:
- **`fromAsn1(obj)`** — Deserializes a SignedData structure from ASN.1
- **`toAsn1()`** — Serializes the SignedData structure to ASN.1 (triggers `sign()` if no content info exists)
- **`addSigner(signer)`** — Registers a signer with a private key, certificate/issuer info, digest algorithm (SHA-1/256/384/512, MD5), and optional authenticated attributes
- **`sign(options)`** — Computes and attaches digital signatures; supports detached signing mode

## Usage Example

```javascript
const p7 = require('./pkcs7-modified');
const forge = require('node-forge');

// Create a signed message
const signedData = p7.createSignedData();
signedData.content = forge.util.createBuffer('Hello, world!');

signedData.addSigner({
  certificate: myCert,               // forge certificate object or PEM string
  key: myPrivateKey,                 // forge private key object or PEM string
  digestAlgorithm: forge.pki.oids.sha256,
  authenticatedAttributes: [
    { type: forge.pki.oids.contentType, value: forge.pki.oids.data },
    { type: forge.pki.oids.messageDigest }
  ]
});

signedData.sign();

// Export to PEM
const pem = p7.messageToPem(signedData);

// Parse from PEM
const parsed = p7.messageFromPem(pem);
```

## Notes

- Requires `node-forge` either at `../node-forge/` (relative) or `./node_modules/node-forge/` (local), with automatic fallback between the two paths
- Only flat nesting is supported; nested ContentInfo structures beyond a single `Data` type are not implemented
- CRL parsing is stubbed but not yet implemented
