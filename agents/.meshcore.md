Meshcore.js is the primary agent-side core module for MeshCentral, responsible for bootstrapping the mesh agent runtime, managing platform compatibility, user session detection, and domain/identity state resolution.

## Key Components

- **`getDomainInfo()`** — Queries the current machine's domain membership via WMI (Windows) or `realm` CLI (Linux), returning name, domain, and `PartOfDomain` flag.
- **`getJoinState()`** — Detects Windows identity join state (0=none, 1=Azure AD, 2=On-prem AD, 3=Hybrid, 4=Microsoft Account) via registry inspection.
- **`getLoggedOnUserBySessionId(sessionId)`** — Reads the Windows registry to resolve a logged-on username from a session ID.
- **`getLogonCacheKeys()`** — Recursively reads the Windows IdentityStore LogonCache registry tree and returns grouped user objects with UPN, SAM, and SID arrays.
- **`getCoreTranslation()`** — Loads localized UI strings for consent/notification dialogs (terminal, desktop, file access) with English fallbacks.
- **`__readdirSync_fix()`** — Patches `fs.readdirSync` on 32-bit Windows agents running on 64-bit Windows to inject the missing `sysnative` directory entry.
- **`bcdOK()`** — Validates that the Windows agent pointer size matches the OS architecture.
- **Mesh Rights constants** — Bitmask flags (e.g., `MESHRIGHT_REMOTECONTROL`, `MESHRIGHT_NOTERMINAL`) used for access control decisions.

## Usage Example

```javascript
// Resolve domain membership on agent startup
var domainInfo = getDomainInfo();
console.log(domainInfo.PartOfDomain ? 'Domain: ' + domainInfo.Domain : 'Workgroup');

// Check Windows identity join state
var joinState = getJoinState();
// Returns: 0=local, 1=AzureAD, 2=OnPrem, 3=Hybrid, 4=MSAccount

// Get localized consent prompt strings
var t = getCoreTranslation();
var prompt = t.desktopConsent.replace('{0}', 'AdminUser');
// → "AdminUser requesting remote desktop access. Grant access?"
```
