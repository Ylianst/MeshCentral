Defines custom error types for the node-rdpjs RDP protocol library, providing structured error handling across fatal, protocol, and implementation error categories.

## Key Components

- **`FatalError`** — Represents a critical, program-stopping error. Accepts `message` and `code` (defaults to `'NODE_RDP_CORE_ERROR_NO_ERROR_CODE'`). Inherits from `Error`.
- **`ProtocolError`** — Non-fatal error for RDP protocol violations. Accepts `code` and optional `message`. Inherits from `Error`.
- **`ImplementationError`** — Non-fatal error for unimplemented or unsupported functionality. Accepts `code` and optional `message`. Inherits from `Error`.

All three constructors call `Error.captureStackTrace(this)` to preserve stack traces for debugging.

## Usage Example

```javascript
const { FatalError, ProtocolError, ImplementationError } = require('./error');

// Fatal — unrecoverable condition
throw new FatalError('Connection failed', 'NODE_RDP_CONNECT_FAILED');

// Protocol — unexpected data from remote end
emitter.emit('error', new ProtocolError('NODE_RDP_BAD_PACKET', 'Unexpected PDU type'));

// Implementation — feature not yet supported
emitter.emit('error', new ImplementationError('NODE_RDP_UNIMPLEMENTED', 'Bitmap compression not supported'));

// Type checking
if (err instanceof FatalError) {
  process.exit(1);
} else if (err instanceof ProtocolError) {
  // attempt recovery or log
}
```

## Notes

- Only `FatalError` provides a default error code; `ProtocolError` and `ImplementationError` require an explicit `code` argument.
- All errors extend the native `Error` class via Node.js `util.inherits`, making them compatible with standard `instanceof` checks and error-handling middleware.
