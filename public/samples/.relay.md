Provides a factory function for creating WebSocket-based relay connections to a MeshCentral server via the `/meshrelay.ashx` endpoint.

## Key Components

### `createMeshConnection(connectionId)`

Factory function that returns a connection object with the following members:

| Member | Type | Description |
|--------|------|-------------|
| `connectionId` | `string` | Unique relay session identifier |
| `state` | `number` | Connection state: `0` = disconnected, `1` = connecting, `2` = peer connected |
| `onStateChanged` | `function` | Callback fired on state transitions `(obj, newState)` |
| `onData` | `function` | Callback fired when data is received `(obj, data)` |
| `connect()` | `function` | Opens the WebSocket connection, returns `obj` for chaining |
| `send(data)` | `function` | Sends data only when state is `2` (peer connected) |

### Connection Protocol

The peer handshake is signal-based: the server sends `'c'` to indicate a peer has joined, at which point `state` advances to `2` and subsequent messages are forwarded to `onData`.

## Usage Example

```javascript
var conn = createMeshConnection('my-session-id-123');

conn.onStateChanged = function (obj, state) {
    console.log('State changed to', state);
};

conn.onData = function (obj, data) {
    console.log('Received data:', data);
};

conn.connect();

// Send data once peer is connected (state === 2)
conn.send('Hello peer!');
```

## Notes

- **Known bug:** `onStateChanged` callbacks are invoked as `onStateChanged(obj, state)` (bare function call) rather than `obj.onStateChanged(obj, state)`, which will throw a `ReferenceError` unless `onStateChanged` is also defined in the outer scope.
- The condition `(obj.state = 1)` in the message handler uses assignment (`=`) instead of comparison (`==`), so it always evaluates as truthy.
- Binary messages are supported via `arraybuffer` binary type on the WebSocket.
