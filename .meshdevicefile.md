Handles WebSocket-based file download relay sessions between MeshCentral agents and browser clients, managing authentication, peer connection orchestration, and bidirectional data routing for device file transfers.

## Key Components

- **`CreateMeshDeviceFile(parent, ws, res, req, domain, user, meshid, nodeid)`** — Factory function that creates and initializes a file relay session object
- **`obj.close(arg)`** — Disconnects the relay session; `arg=1` performs a soft WebSocket close, `arg=2` forces a hard TCP socket close
- **`obj.sendAgentMessage(command, user, domainid)`** — Routes a command to a connected agent directly or via a peer server, enforcing `MESHRIGHT_REMOTECONTROL` permissions
- **`performRelay()`** — Core relay logic that pairs two connections (agent WebSocket + HTTP response), negotiates the file transfer protocol, and sets up message forwarding
- **`cleanRemoteAddr(addr)`** — Strips the `::ffff:` prefix from IPv4-mapped IPv6 addresses

## Usage Example

```javascript
// Instantiated internally by MeshCentral's HTTP/WebSocket router
const meshDeviceFile = require('./meshdevicefile');

// Called when a file download relay request arrives
const relaySession = meshDeviceFile.CreateMeshDeviceFile(
    parent,   // MeshServer parent object
    ws,       // WebSocket connection (or null for HTTP)
    res,      // HTTP response object (or null for WS)
    req,      // Express request (carries query params: id, f, rauth)
    domain,   // Domain configuration object
    user,     // Authenticated user object (or null if relay-auth)
    meshid,   // Target mesh group ID
    nodeid    // Target device node ID
);

// Gracefully close the session
relaySession.close(1);
```

## Authentication Flow

Connections require either a valid `user` session or a signed `rauth` relay cookie decoded via `decodeCookie` with a 4-hour TTL. Unauthenticated connections are immediately dropped with a debug log entry.
