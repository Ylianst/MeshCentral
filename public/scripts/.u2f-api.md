Google's FIDO U2F JavaScript API client library that enables hardware security key authentication in web browsers by bridging communication between web pages and U2F browser extensions or native authenticator apps.

## Key Components

- **`u2f.EXTENSION_ID`** — Chrome packaged app extension identifier for U2F communication
- **`u2f.MessageTypes`** — Enum of message types for register/sign request-response communication
- **`u2f.ErrorCodes`** — Enum of response status codes (`OK`, `BAD_REQUEST`, `DEVICE_INELIGIBLE`, `TIMEOUT`, etc.)
- **`u2f.getMessagePort(callback)`** — Core routing function that detects the runtime environment and returns the appropriate communication port (Chrome extension, Android Authenticator, iOS, or iframe)
- **`u2f.WrappedChromeRuntimePort_`** — Adapter wrapping `chrome.runtime.Port` to a `MessagePort`-compatible interface
- **`u2f.WrappedAuthenticatorPort_`** — Adapter for Android Chrome that launches the Authenticator app via an intent URL
- **`u2f.formatSignRequest_()`** — Builds sign request payloads compatible with JS API v1.0 or v1.1
- **`u2f.formatRegisterRequest_()`** — Builds registration request payloads compatible with JS API v1.0 or v1.1

## Usage Example

```javascript
// Registration
u2f.register(appId, registerRequests, registeredKeys, function(response) {
  if (response.errorCode) {
    console.error('Registration failed:', response.errorCode);
    return;
  }
  // Send response.registrationData and response.clientData to server
});

// Authentication / Sign
u2f.sign(appId, challenge, registeredKeys, function(response) {
  if (response.errorCode) {
    console.error('Sign failed:', response.errorCode);
    return;
  }
  // Send response.signatureData and response.clientData to server
});
```

## Notes

- Only initializes if `window.u2f` is not already defined, preventing duplicate loading
- Automatically detects Chrome (desktop/Android/iOS) vs. fallback iframe transport
- Supports both JS API v1.0 and v1.1 request formats via `js_api_version`
