Extends `TightDecoder` to handle TightPNG-encoded rectangles in the noVNC HTML5 VNC client, rendering PNG image data directly to the display.

## Key Components

- **`TightPNGDecoder`** — Subclass of `TightDecoder` that overrides rectangle handling for PNG-specific Tight encoding
- **`_pngRect(x, y, width, height, sock, display, depth)`** — Reads raw PNG data from the socket buffer and renders it to the display via `display.imageRect()`
- **`_basicRect(ctl, x, y, width, height, sock, display, depth)`** — Overridden to throw an error, since `BasicCompression` is invalid in TightPNG mode

## Usage Example

```javascript
import TightPNGDecoder from './tightpng.js';

const decoder = new TightPNGDecoder();

// Called internally by the VNC protocol handler when a TightPNG rect is received
const complete = decoder._pngRect(
    x, y, width, height,
    sock,     // WebSocket abstraction providing raw bytes
    display,  // Display object with imageRect() for rendering
    depth     // Color depth
);

if (!complete) {
    // Insufficient data in buffer; retry when more data arrives
}
```

> **Note:** `TightPNGDecoder` is not intended to be used directly. It is instantiated by the noVNC protocol engine when the server advertises TightPNG encoding. Calling `_basicRect` will throw, enforcing that only PNG-compressed subrectangles are processed.
