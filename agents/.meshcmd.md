MeshCmd is the command-line tool entry point for Intel AMT (Active Management Technology) and MeshCentral operations, handling device discovery, AMT configuration, remote management, and mesh network interactions.

## Key Components

- **AMT Management** — Interfaces with Intel AMT via MEI (Management Engine Interface), LMS (Local Management Service), and WebSocket-based AMT stacks (`amtstack`, `wsstack`)
- **Device Discovery** — Implements multicast/broadcast UDP discovery using IPv4 (`239.255.255.235`) and IPv6 (`FF02:0:0:0:0:0:0:FE`) membership groups
- **Network Utilities** — TCP server (`tcpserver`), broadcast/multicast sockets, and HTTP client support
- **SMBIOS Integration** — Reads `SMBiosTables` for hardware-level device identification
- **Embedded Web App** — Bundles a gzip+Base64-encoded MeshCommander LMS web app (`_IntelAmtWebApp`) with ETag versioning for local AMT UI serving
- **RCS Protocol** — Implements Remote Configuration Service messaging (protocol version 1)
- **Global Settings** — Centralized `settings` object controlling runtime behavior across all modules

## Usage Example

```javascript
// Typical CLI invocation patterns (meshcmd is run as a standalone binary):

// Discover Intel AMT devices on the local network
meshcmd discover

// Activate/configure AMT on the local device
meshcmd amtconfig --url wss://meshserver.example.com --id meshNodeId

// Connect a local port to a remote device via MeshCentral
meshcmd route --host meshserver.example.com --port 16992 --localport 4433

// Check local AMT MEI state
meshcmd amtinfo
```

## Notes

- `meshCmdVersion` is a build-time placeholder replaced dynamically with the MeshCentral release version
- `globalDebugFlags` can enable IDER (IDE-Redirect) debug output (flag `1`)
- The embedded `_IntelAmtWebApp` is MeshCommander v0.9.5, served locally over LMS when no external server is available
