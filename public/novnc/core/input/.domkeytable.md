Maps HTML DOM key values to VNC/X11 keysyms for special keys that cannot be handled via Unicode codepoints, used by the noVNC client for keyboard event translation.

## Key Components

- **`DOMKeyTable`** — The primary export; a plain object keyed by [W3C UI Events key values](https://www.w3.org/TR/uievents-key/) where each entry is a 4-element array: `[generic, left, right, numpad]` keysyms.
- **`addStandard(key, standard)`** — Registers a key that maps identically across all contexts (same keysym for left/right/numpad).
- **`addLeftRight(key, left, right)`** — Registers a modifier key with distinct left/right keysyms (e.g., `Shift_L` vs `Shift_R`). The array layout is `[left, left, right, left]`.
- **`addNumpad(key, standard, numpad)`** — Registers a key with a distinct numpad variant (e.g., `XK_Delete` vs `XK_KP_Delete`). Layout is `[standard, standard, standard, numpad]`.

**Covered key categories:** Modifier keys, whitespace, navigation, editing, UI, device, IME/composition, function keys (F1–F35), multimedia, audio, application launchers, browser keys, and numpad arithmetic operators.

## Usage Example

```javascript
import DOMKeyTable from "./domkeytable.js";

// Look up a key by its W3C DOM key value
const shiftKeysyms = DOMKeyTable["Shift"];
// => [XK_Shift_L, XK_Shift_L, XK_Shift_R, XK_Shift_L]
// Index 0: generic, 1: left-side, 2: right-side, 3: numpad

const [generic, left, right, numpad] = DOMKeyTable["Enter"];
// generic/left/right => XK_Return, numpad => XK_KP_Enter

// Keys not in the table should be handled via Unicode codepoint instead
if (DOMKeyTable[event.key]) {
    const keysym = DOMKeyTable[event.key][locationIndex];
}
```
