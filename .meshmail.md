E-mail transport module for MeshCentral that handles sending system emails via SendGrid, SMTP, or Sendmail, with support for multi-language HTML/text templates.

## Key Components

- **`CreateMeshMail(parent, domain)`** — Factory function that instantiates the mail module and configures the appropriate transport (SendGrid, SMTP via nodemailer, or Sendmail)
- **`getTemplate(name, domain, lang)`** — Loads HTML and plain-text email templates from disk with language/locale fallback chain (domain-specific → override path → default English)
- **`EscapeHtml(x)`** — Sanitizes strings for safe HTML embedding
- **`getStrBetween(str, start, end)`** — Extracts a substring between two markers (used for template token replacement)
- **`removeStrBetween(str, start, end)`** — Removes content between two markers
- **`strZone(str, marker, keep)`** — Conditionally keeps or removes named `<area-*>` sections in template content

## Transport Configuration

The module selects a transport based on `config`:

| Config Key | Transport |
|---|---|
| `sendgrid` | `@sendgrid/mail` SDK |
| `smtp` | `nodemailer` (supports TLS, OAuth2, Gmail) |
| `sendmail` | `nodemailer` sendmail transport |
| `smtp.name = 'console'` | Debug console output |

## Usage Example

```javascript
// Instantiated internally by MeshCentral — not called directly by consumers
const meshMail = require('./meshmail').CreateMeshMail(parent, domain);

// Emails are queued in meshMail.pendingMails and sent with configurable delay
// Default delay: 5 minutes (obj.emailDelay = 5 * 60 * 1000)

// Template files are resolved in order:
// 1. domain.webemailspath/translations/<name>_<lang>.html
// 2. domain.webemailspath/<name>.html
// 3. parent.webEmailsPath/translations/<name>_<lang>.html
// 4. parent.webEmailsPath/<name>.html
```
