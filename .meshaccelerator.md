A child process worker for MeshCentral that handles CPU-intensive or delegated operations offloaded from the main process, including cryptographic signing and certificate-based state management.

## Key Components

- **`processMessage(message)`** — Main message dispatcher handling IPC messages from the parent process via `process.on('message')`
- **`sign` action** — Performs SHA-384 cryptographic signing using Node.js `crypto`, with retry logic for OpenSSL shared library load errors (`ERR_OSSL_DSO_COULD_NOT_LOAD_THE_SHARED_LIBRARY`)
- **`setState` action** — Initializes the local `certStore` with certificate/key data sent from the parent
- **`indexMcRec` action** — Triggers delayed (5-second) indexing of `.mcrec` files via `mcrec.js`
- **`disconnect` handler** — Ensures the child process exits when the parent disconnects

## Usage Example

This module runs as a forked child process. The parent communicates via IPC:

```javascript
// Parent process: fork the accelerator
const { fork } = require('child_process');
const accelerator = fork('meshaccelerator.js');

// Initialize certificate store in the child
accelerator.send({ action: 'setState', certs: myCertsArray });

// Request a SHA-384 signature using a cert by index
accelerator.send({
  action: 'sign',
  key: 0,              // index into certStore, or a raw key string
  data: binaryDataStr  // binary string to sign
});

// Receive the signed result
accelerator.on('message', (signature) => {
  // signature is a binary string or null on failure
  console.log('Received signature:', signature);
});

// Trigger .mcrec file indexing (delayed 5 seconds)
accelerator.send({ action: 'indexMcRec', data: '/path/to/file.mcrec' });
```

## Notes

- Keys in `sign` can be passed as a **numeric index** into `certStore` (set via `setState`) or as a **raw key value**
- Returns `null` to the parent on signing failure
