Intel(R) AMT Setup.bin file parser and encoder for parsing, decoding, and constructing AMT provisioning configuration files used in Intel Active Management Technology deployments.

## Key Components

### Constants
- **`AmtSetupBinSetupGuids`** — Array of 4 binary GUIDs identifying Setup.bin file versions (v1–v4)
- **`AmtSetupBinVarIds`** — Lookup table mapping module/variable IDs to types, descriptions, and enum values for two AMT modules:
  - Module `1`: MEBx settings (passwords, firmware update, power package)
  - Module `2`: Network/provisioning settings (PKI, FQDN, VLAN, KVM, IPv6, certificates, etc.)

### Functions
- **`AmtSetupBinCreate(version, flags)`** — Creates a new empty Setup.bin object with initialized header fields and an empty records array
- **`AmtSetupBinDecode(file)`** — Parses a raw binary Setup.bin string into a structured JavaScript object, including header metadata, data records, and typed variable entries (with descrambling support)
- **`AmtSetupBinEncode(obj)`** — *(partial)* Serializes a Setup.bin object back to a binary file string

## Usage Example

```javascript
// Decode an existing Setup.bin file
const fs = require('fs');
const rawFile = fs.readFileSync('setup.bin', 'binary');
const parsed = AmtSetupBinDecode(rawFile);

if (!parsed) {
  console.error('Invalid or unrecognized Setup.bin file');
} else {
  console.log('AMT File Version:', parsed.fileType);
  console.log('Major Version:', parsed.majorVersion);
  console.log('Records consumed:', parsed.dataRecordsConsumed);

  parsed.records.forEach((record, i) => {
    console.log(`Record ${i}:`, record.variables);
  });
}

// Create a new Setup.bin structure
const newSetup = AmtSetupBinCreate(2, 0);
newSetup.records.push({ typeIdentifier: 1, flags: 1, variables: [] });
```

## Notes

- Variable types: `0` = binary string, `1` = char (byte), `2` = short (2 bytes), `3` = int (4 bytes)
- Records flagged with bit `2` in `r.flags` are descrambled via `AmtSetupBinDescrambleRecordData` before parsing
- File is structured as 512-byte chunks; the header occupies the first chunk and each data record occupies subsequent chunks
