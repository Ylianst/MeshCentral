A sample MeshCentral bot client that connects to a MeshCentral server via WebSocket and handles basic inter-user messaging, auto-reconnection, and server event processing.

## Key Components

- **`serverConnect()`** — Core function that establishes and manages the WebSocket connection to the MeshCentral control endpoint (`control.ashx`), handling authentication, proxy configuration, and automatic reconnection on disconnect.
- **Authentication modes** — Supports three methods: cookie-based (`--loginkey`), password-based (`--loginuser`/`--loginpass`) with optional TOTP (`--token`), and server login key via URL query string.
- **WebSocket event handlers** — Processes `serverinfo`, `userinfo`, and `interuser` actions; echoes back inter-user messages when no target is configured (useful for testing).
- **CLI argument parsing** — Uses `minimist` to handle `--url`, `--loginuser`, `--loginpass`, `--token`, `--loginkey`, `--nocertcheck`, and `--proxy` flags.

## Usage Example

```bash
# Basic connection with password auth
node meshbot.js run --url wss://my-server:443 --loginuser admin --loginpass secret

# With 2FA token and proxy
node meshbot.js run --url wss://my-server:443 --loginuser admin --loginpass secret \
  --token 123456 --proxy http://proxy.local:8080

# Send an inter-user message to a specific user
node meshbot.js run --url wss://my-server:443 --loginkey abc123 \
  --targetuser user//domain//alice

# Skip TLS certificate validation (dev/self-signed certs)
node meshbot.js run --url wss://localhost:443 --loginpass secret --nocertcheck
```

> **Note:** Requires `ws` and `minimist` npm packages. Optionally requires `https-proxy-agent` when using `--proxy`.
