MeshCentral plugin that exposes two HTTP routes for OpenFrame integration: MSH agent config generation and device connectivity status queries, with multi-tenant domain isolation.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `openframe` | Plugin factory | Main plugin entry point called by MeshCentral's plugin handler |
| `hook_setupHttpHandlers` | Hook | Registers HTTP routes on the MeshCentral Express app |
| `deriveTenantDomain` | Helper | Extracts the pod's tenant domain from config to enforce cross-tenant isolation |
| `corsHeaders` | Helper | Applies permissive CORS headers to all responses |

### Routes

| Route | Method | Description |
|-------|--------|-------------|
| `/generate-msh` | `GET` | Generates a downloadable `.msh` agent config file for a given host |
| `/api/deviceStatus` | `GET` | Returns online status and last connection info for a `node/<domain>/<id>` |
| `/generate-msh`, `/api/*` | `OPTIONS` | CORS preflight handler |

### Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `MESH_DIR` | `/opt/mesh` | Directory containing `mesh_id` and `mesh_server_id` files |
| `MESH_DEVICE_GROUP` | `''` | Device group name written into the generated MSH file |

## Usage Example

```javascript
// Registered automatically by MeshCentral's plugin loader.
// The plugin reads mesh identity files and registers routes on startup:

// GET /generate-msh?host=https://mesh.example.com
// → Downloads meshagent.msh with correct MeshServer URL

// GET /api/deviceStatus?id=node/acme/abc123
// → Returns:
// {
//   "nodeId": "node/acme/abc123",
//   "online": true,
//   "lastConnectTime": 1718000000000,
//   "lastConnectAddr": "203.0.113.42:49200"
// }
```

> **Tenant isolation:** The `deviceStatus` route returns `404` (not `403`) for node IDs belonging to a different tenant domain to avoid acting as an oracle for cross-tenant device enumeration.
